## 2. 相对截图做了什么改动

| # | 问题 | 方案 |
| --- | --- | --- |
| 1 | 里程碑是四个孤立圆点，看不出进度 | 连成**带填充进度的航程线**；当前节点加光晕，超期转红，悬停出「计划 vs 实际」 |
| 2 | 九个筛选器平铺占两行 | 保留高频三个，其余收进「更多筛选」，已生效条件以可单独删除的胶囊回显 |
| 3 | 数字与文字同字体，柜号难核对 | 柜号 / PI 号 / 报关单号 / 金额 / 日期一律**等宽 + 等宽数字**，小数点自然对齐 |
| 4 | 「快捷更新」常驻右栏约 300px，空着也占位，把里程碑列挤出屏幕 | 改为**勾选后从底部升起的操作条**，表格永远满宽 ← *这条与截图不同，如更习惯右栏可改回* |
| 5 | 停滞 / 超期 / 负毛利 / 退税未关联要靠人翻 | 统一语义色（绿=正常 / 琥珀=待办 / 红=异常）+ 行首色条 + 看板「今天要处理什么」清单 |

## 3. 设计语言

**色彩** — 主色一个（航线蓝 `#3B5BD6`），语义色三个，严格分离：
蓝色永远表示「系统的强调」，绿 / 琥珀 / 红永远表示「业务的状态」。

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| 主色 · 航线蓝 | `#3B5BD6` | `#8098F5` |
| 松绿 · 完成 / 已放行 | `#0E8F63` | `#41C596` |
| 琥珀 · 待办 / 预警 | `#A96A00` | `#D79A34` |
| 珊瑚 · 异常 / 亏损 | `#C93B3B` | `#E97070` |
| 纸面 | `#F3F6FA` | `#0C121B` |
| 导航轨 | `#0B1220`（两个主题都是深色，作为品牌锚点） | `#070C14` |

中性色带轻微蓝偏，不用纯灰。

**字体** — 中文走系统栈（PingFang / 鸿蒙 / 微软雅黑 / Noto），不外链网络字体，
内网与离线环境不会掉字；代码型数据走等宽栈。字号阶梯 11.5 / 12.5 / 13 / 14 / 25 / 27。

**交互约定**

- 就地编辑优先：动态、状态、里程碑日期点一下就改，不必进详情页
- 批量是一等公民：勾选 → 底部操作条 → 一次写完动态 + 日期 + 状态
- 详情用抽屉不跳页，列表滚动位置与筛选不丢
- 破坏性操作必有撤销（5 秒）
- 每个手势都有按钮替身，不依赖长按 / 拖拽
- 空态说人话：写「当前筛选下没有进行中的批次，试试关掉『仅进行中』」

## 4. 技术选型

**推荐：Next.js 15 全栈单服务 + Prisma + SQLite。**
前后端同一工程、同一进程、同一端口；数据库是一个 `.db` 文件，拷走即备份。

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 运行时 | Node.js 20 LTS | 群晖 / 任何 Linux 都能装，只需一个运行时 |
| 框架 | Next.js 15 (App Router) + React 19 | 页面与 API 同工程同端口，省掉前后端分离的部署复杂度 |
| 语言 | TypeScript | 金额、汇率、状态机靠类型挡低级错误 |
| 样式 | Tailwind CSS v4 | 零运行时；原型的 token 体系可直接搬为 Tailwind 变量 |
| 组件 | shadcn/ui (Radix) | 源码进仓库，不是黑盒依赖，可按设计稿随意改 |
| 表格 | TanStack Table v8 | 只有逻辑没有样式；列固定 / 排序 / 行选择 / 虚拟滚动够用 |
| 数据层 | Prisma ORM | SQLite / MySQL 同一套 schema，迁移与类型生成一条龙 |
| 数据库 | SQLite（默认）→ MySQL 8 | 见下方切换路径 |
| 登录 | Cookie Session + argon2 | 自建约 200 行，不引入 OAuth 体系 |
| Excel | SheetJS / ExcelJS | 服务端导入导出，模板对齐现有台账 |
| 图表 | Recharts | 用量不大；嫌重可直接用原型里的手写 SVG |
| 定时任务 | node-cron（进程内） | 汇率刷新 / 超期扫描 / 退税提醒，不需要独立调度器 |

**明确不引入**：Kafka、RabbitMQ（数据库表当队列足够）、Redis（进程内缓存够用）、
Elasticsearch（SQLite FTS5 / MySQL 全文索引够用）、Oracle / PostgreSQL（超配）、
微服务拆分、K8s。

### SQLite → MySQL 切换路径

1. `schema.prisma` 的 `provider` 由 `sqlite` 改 `mysql`，换 `DATABASE_URL`，跑一次
   `prisma migrate` —— 应用代码零改动。
2. 迁移目录按方言分开维护（`migrations-sqlite` / `migrations-mysql`），两边 DDL 不同。
3. schema 只用两库都支持的类型：不用 SQLite 特有写法，不用 MySQL `ENUM`
   （状态存字符串 + 应用层枚举）。
4. 存量数据用一次性脚本 `scripts/migrate-to-mysql.ts` 搬迁，它本身也是备份工具。

> ⚠️ **金额一律用整数存。** SQLite 没有真正的 DECIMAL，浮点会让核算和退税凑不平账。
> 约定：金额存「分」（`BigInt`），汇率存 6 位小数的整数（`6.7392` → `6739200`），
> 只在展示层格式化。**这条要在第一行代码之前定下来**，后改成本极高。

### 部署

- 裸机 / 群晖 SSH：`npm ci && npm run build && npm start`，默认 3000 端口，`pm2` 或 systemd 守护
- Docker（群晖套件推荐）：一个镜像 + 一个数据卷，`docker compose up -d`，没有第二个容器
- 备份：SQLite 阶段定时拷 `.db` 文件；MySQL 阶段 `mysqldump`
- 升级：拉代码 → build → 重启，迁移在启动时自动执行

## 5. 数据模型草案

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `customer` | code, name, country, sales_id, credit_level, sinosure_limit | 客户主档，中信保额度挂这 |
| `pi` | pi_no, customer_id, sales_id, signed_at, amount_cents, currency, seller_id | PI 取号即建档，全系统主线索 |
| `order_costing` | pi_id, purchase_cost, receivable, payable, profit_rate, status | 订单核算，成本超支自动进复核 |
| `shipment` | batch_no, pi_id, country, term, mode, fcl, container_no, carrier, pod, release_state | 跟单表一行 = 一个出运批次 |
| `shipment_milestone` | shipment_id, kind, planned_on, actual_on | 交期 / 装柜 / 进仓 / ATD / ETA，一行一个节点 |
| `shipment_note` | shipment_id, body, happened_on, author_id | 动态是流水而非单字段，才有历史 |
| `tax_invoice` | declare_month, batch, buyer_id, seller, invoice_no, amount, tax, customs_no, pi_id? | `pi_id` 可空 = 未关联订单行 |
| `payment` | pi_id, direction, amount_cents, currency, paid_on, account_id | 收付款，汇总到资金看板 |
| `audit_log` | actor_id, entity, entity_id, action, before, after, at | 改动全留痕，对应「审计日志」模块 |

**权限**：两个维度组合，不做复杂 RBAC 树。
*角色*（管理员 / 业务员 / 跟单 / 采购 / 财务 / 只读）决定能进哪些模块、能否修改；
*数据范围*（本人 / 本组 / 全部）决定看到哪些行。
财务字段（成本、利润率、应付）对业务员默认隐藏，可按角色单独开。
