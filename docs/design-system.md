# 设计规范

令牌全部定义在 `src/styles/tokens.css`，改那一个文件就能改全站。
这篇解释每条规则背后的理由 —— 光有色值表，下一个人还是不知道什么时候该用哪个。

---

## 1. 颜色：主色可换，语义色三个固定，两者严格分离

**主色永远表示「系统的强调」，绿 / 琥珀 / 红永远表示「业务的状态」。**

这条分离是整套配色最重要的一条。一旦主按钮用了绿色，用户就分不清
「这是一个可点的按钮」和「这一行是正常状态」。

| 角色 | 浅色 | 深色 | 用在哪 |
| --- | --- | --- | --- |
| 主色 · 航线蓝（默认） | `#3B5BD6` | `#7F9BFF` | 主按钮、当前节点、进度填充、选中行 |
| 松绿 | `#0B8A5F` | `#3FC493` | 已放行、已完结、利润率健康、税额 |
| 琥珀 | `#A2650A` | `#DBA33F` | 待办、未放行、利润率预警、额度接近上限 |
| 珊瑚 | `#C8393C` | `#EF7676` | 停滞、里程碑超期、负毛利、未关联发票 |
| 紫 | `#6A45C2` | `#AB8FF0` | 分批标签、批量操作、第二开票主体 |
| 纸面 | `#EEF2F8` | `#080D16` | 页面背景 |
| 表面 | `#FFFFFF` | `#101827` | 卡片、表格、弹层 |

中性色带轻微蓝偏，不用纯灰 —— 纯灰在长时间盯的台账里显脏。
**导航轨跟着主题走**，不再两个主题都用深色：浅色模式下左边一条深色竖条
跟右边的浅色内容区看着像两个应用拼起来的，品牌锚点不值这个代价。

### 主色可换：令牌分两层

顶栏「外观」里能换五套主色。做法不是写五份主题，而是把令牌拆成两层：

- **调色板层** `--acc-l-*` / `--acc-d-*`：一套配色声明它明暗两条阶梯长什么样，
  命名只说位置（l = 浅色那条，d = 深色那条），不说用途；
- **语义层** `--accent` / `--accent-hi` / `--accent-soft`…：只做一件事 —— 挑一条。

好处是「明暗」和「配色」互不知情：加一套色 = 加一个五行的块，不用去动明暗
那两大段；5 套色 × 3 种明暗可以自由组合，也不用写 15 份。
全站七十多处 `var(--accent)` 一处没改。

| 主色 | 色相 | 浅色 | 深色 | 一句话 |
| --- | --- | --- | --- | --- |
| 航线蓝 harbor | 269° | `#3B5BD6` | `#7F9BFF` | 默认 |
| 远洋蓝 cerulean | 240° | `#0170A6` | `#2EACF5` | 更冷一档 |
| 松石绿 teal | 192° | `#017976` | `#30B8B4` | 沉一点 |
| 暮山紫 dusk | 306° | `#8149B2` | `#B68CE1` | 重一点 |
| 墨石 graphite | 264°（彩度 15%） | `#61697A` | `#9BA2B1` | 近乎无彩，只留状态色 |

**选色受两条硬约束，不是挑好看的。**

1. **不能跟状态色撞。** 状态色的色相是 jade 162° / amber 68° / coral 24°。
   主色一旦落进这些邻域，一个「主要按钮」就会被读成「成功」或「报错」——
   那正好推翻了上面那条分离原则。所以候选全在冷色半区（190°–310°），
   外加一个近乎无彩的墨石。绿色和橙色看着好看，但在这个系统里它们已经有
   工作了。松石绿 192° 离 jade 只有 30°，彩度额外压到 75% 才敢放进来。
2. **落在 sRGB 色域内。** 阶梯是按 OKLCH 的固定明度档算的，而青色一带
   （190°–240°）在中明度上能吃的彩度只有蓝色的一半左右。硬给会被浏览器裁
   通道、连色相一起偏掉，所以每一档的彩度都单独收到**自己那一档**的上限
   以内 —— 这也是青色两套看起来比蓝紫两套素的原因，不是没调，是色域就这么大。

白字压在浅色主色上的对比度 5.2–6.0，深色那条 7.3–8.0，都过 AA。

主色也管品牌标记的渐变（`--brand-1` / `--brand-2`）和登录页那块深色面板。
面板底色仍是品牌自己的深海军蓝，只有最亮那一档、流线、光晕和几行次要文字
掺进主色 —— 那几行字原来写死了一组蓝灰，换成松石绿之后帆标和按钮都绿了、
只有文字还泛蓝，一块面板像调了两次色。

选色器里的小圆点画成**两色斜切**（浅色那条 / 深色那条）。一来它自己就说明了
「这套色明暗两边各长什么样」，二来不管弹层此刻是白底还是黑底，总有一半立得住 ——
只画一个色的话，墨石在白底上、松石绿在黑底上都会糊掉。

### 语义色怎么落到行上

有问题的行在**行首**挂一条 3px 色条（`tr[data-tone]`），不是把整行染色。
整行染色在密集表格里会把文字对比度拉垮，而且几行连着变色时看起来像故障。

## 2. 字号与字体

中文走系统栈（PingFang / 鸿蒙 / 微软雅黑 / Noto），**不外链网络字体** ——
内网与离线环境不会掉字，首屏也不用等字体。

**代码型数据一律等宽 + 等宽数字**：柜号、PI 号、报关单号、金额、日期、批次号。
`font-variant-numeric: tabular-nums` 让小数点自然对齐，财务扫一列就能看出量级。
这是 `.num` / `.mono` 这两个类做的唯一一件事。

| 令牌 | 值 | 用在哪 |
| --- | --- | --- |
| `--fs-xs` | 11.5px | 胶囊、标签、次要说明 |
| `--fs-sm` | 12.5px | 表头、辅助信息、按钮小号 |
| `--fs-md` | 13px | 表格正文、菜单项 |
| `--fs-base` | 14px | 正文 |
| `--fs-lg` | 16px | 抽屉标题、卡片强调 |
| `--fs-xl` | 20px | 窄屏页面标题 |
| `--fs-2xl` | 26px | 页面标题、KPI 数值 |
| `--fs-3xl` | 32px | 登录页主标题 |

## 3. 间距：两档，而且只由容器给

```
--gap-tight  12px   一簇同类小件内部（KPI 卡、报表卡）
--gap-block  16px   页面级的块之间（页头、工具条、面板、表格、图表行）
```

两档就够。档位一多，每次都要挑一个，挑出来的结果反而不齐。

**规矩：块与块之间的间距一律由容器的 `gap` 提供，不用相邻兄弟外边距。**

```css
/* ✗ 别这么写 */
.card + .card { margin-top: 16px; }

/* ✓ 交给容器 */
.page-body { display: grid; gap: var(--gap-block); }
```

理由不是洁癖：**相邻兄弟选择器不知道自己在什么布局里**。
`.card + .card { margin-top }` 在纵向堆叠时是对的，可一旦这些卡片是某个 grid 行的
成员（看板的 `.dash-3`），它就叠在 `gap` 上面，把第二张之后的卡片整体压低，
**一行卡片的上边框对不齐**。这个 bug 上线过一次，症状是「有些表格的上边框没对齐」，
而 CSS 里根本搜不到任何跟表格有关的东西。

> ⚠️ `.toolbar` 是 `position: sticky` 的，**不能**放进 `.page-body`。
> grid 项的 sticky 被限制在自己那一行的轨道里，轨道高度就等于它自己 —— 等于失效。
> （flex 项不受这个限制，它的约束是整个 flex 容器。）

## 4. 控件高度只有三档

**24（微） / 30（默认） / 36（大）。** 同一行里的按钮、输入框、下拉一定对得齐 ——
一行控件高低差两像素，整个界面就显得没做完。

圆角同理只有五档：`5 / 7 / 10 / 14 / 18`，加一个 `999` 的胶囊。
嵌套时外层比内层大一档（卡片 14，里面的按钮 7）。

## 5. 表格密度

`[data-density]` 挂在 `<html>` 上，三档联动行高与内边距：

| 档位 | 行高 | 用在什么时候 |
| --- | --- | --- |
| 紧凑 | 44px | 一屏要多看十几行，扫读为主 |
| 标准 | 56px | 默认 |
| 宽松 | 68px | 长时间盯着改，减少误点 |

## 6. 交互约定

- **就地编辑优先**：动态、放行状态、里程碑日期点一下就改，不必进详情页。
  跟单员一天要做几十次，为此进出详情页是纯粹的浪费。
- **批量是一等公民**：勾选 → 底部升起操作条 → 一次写完动态 + 日期 + 状态。
  操作条从底部升起而不是常驻右栏 —— 右栏空着也占 300px，把里程碑列挤出屏幕。
- **详情用抽屉不跳页**：列表滚动位置与筛选不丢；抽屉宽度可拖并记住；
  `J` / `K` 上下换票，跟单员是一票一票往下看的。
- **破坏性操作必有撤销**：6 秒，提示条上画一圈倒计时。
  与其写「5 秒内可撤销」，不如把这 5 秒直接走给用户看。
- **筛选条件写进 URL**：刷新不丢，也能把「当前这一屏」直接发给同事。
- **每个手势都有按钮替身**：不依赖长按 / 拖拽 —— 拖拽只是列宽和侧栏宽度的加速方式，
  不拖也能用。
- **空态说人话**：写「当前筛选下没有批次，试试关掉『仅进行中』」，
  而不是「暂无数据」。空态要回答两件事：为什么空、下一步按哪。

## 7. 表格：四件不肯让步的事

1. **表头冻结** —— 滚到第 80 行仍看得到列名。
2. **前导列冻结** —— 横向滚动时批次号不能滚走，不然对不上行。
3. **边界阴影** —— 冻结列/表头滚出去了才亮阴影，让人看得出「右边 / 下边还有内容」。
   没滚出去不亮，否则平白多两道边。
4. **常驻滚动条** —— macOS 默认的覆盖式滚动条会让人根本不知道右边还有内容。
   全站换成 11px 常驻细滚动条。

> ⚠️ 冻结列的 `<td>` **绝不能被覆盖成 `position: relative`**。
> sticky 一旦失效，后面的列会从它底下透出来。行首色条用 `::before` 绝对定位就够了 ——
> sticky 本身就是定位元素。（这个坑踩过一次，写在这里。）

### 横向滚动条要一直在手边

滚动条长在容器**底边**上，而表格有五六百像素高 —— 页面往下滚一点它就出视口了。
想看右边的列，得先滚到表格底部、找到条、再横着拖回来。列越多越难受。

做法：表格底边被挤出视口时，在视口底部浮出一条**等宽的代理滚动条**，
两边 `scrollLeft` 双向同步；底边重新可见时它自动收起（原生条就在那儿，
再加一条是多余的干扰）。指针靠近时**滚轮直接横滚**，不用瞄准去拖。

**热区必须跟着「当前那条」滚动条走，而不是跟着代理条走。**

页面往下滚到一半，表格底边重新进入视口，代理条就交班给原生条。
第一版把滚轮热区绑在代理条上，于是交班之后悬停横滚跟着一起消失 ——
用户的感受是「有时候有有时候没有」，而且怎么试都试不出规律，
比彻底没做还糟。现在热区认的是有效滚动条的位置：

```
barTop = min(表格底边, 视口底边)
热区   = x 在表格左右之间，且 y ∈ [barTop − 46, barTop + 22]
```

反馈也要分两路给：代理条在用时把它加粗提亮；原生条在用时代理条根本没显示，
改成点亮表格容器的下边缘。同一件事，两种呈现。

滚到左右尽头时**放行**给页面纵向滚 —— 一直拦着，手感像卡住了。

两个实现约束：

- **不能用 `position: sticky`。** sticky 相对最近的滚动容器定位，
  而这里横滚的就是表格容器本身，钉不到视口上。只能量几何 + `fixed`。
- **滚动事件不冒泡。** 真正在滚的是外层 `.canvas` 不是 `window`，
  挂 `window.scroll` 一个事件都收不到。用 `document` 上的**捕获阶段**监听兜底 ——
  中间隔几层滚动容器都能听见。
- 滚轮拦截必须 `passive: false`，否则 `preventDefault` 会被浏览器忽略。

### 交叉高亮

行高亮之外再给列高亮，两条线在鼠标那一格交汇 —— 宽表横向滚过去最容易看串行。

纯 CSS 办不到：同一列的格子不是兄弟节点，CSS 也没法拿一个属性值去匹配另一个属性
（`[data-col=attr(data-hc)]` 不存在）。所以换列时给那一列的格子打 `data-hot`：
事件委托 + 只在列真的变了才写 DOM，一页最多五十来个节点，
比每个格子挂一个 `onMouseEnter` 便宜得多。

高亮刻意做得很淡（主色 6%）—— 它是辅助定位，不是选中态。抢了 `data-sel` 的戏就本末倒置，
所以选中行不受列高亮影响。

## 8. 动效

只有三个时长：`110ms`（状态切换）/ `180ms`（弹层出现）/ `280ms`（抽屉、侧栏）。
缓动统一 `cubic-bezier(0.32, 0.72, 0, 1)` —— 起步快、收尾稳。

**全局尊重 `prefers-reduced-motion`**：开了就把所有动画压到 0.001ms。

动效只用来解释空间关系（抽屉从右边来、批量条从底部升起、弹层贴着触发元素长出来），
不用来装饰。唯一的例外是当前里程碑节点的呼吸光晕 ——
它要在一屏几十个节点里被一眼找到。

### 悬停反馈的分寸

**只在指针停在上面时给回应，动作短、幅度小。** 看板上同时摆着六张卡、几十行数据，
任何一个元素动得太大都会把注意力抢走 —— 反馈是为了确认「我指的是这个」，
不是为了表演。位移一律 ≤3px，倾斜 ≤3.2°。

看板卡片是三层叠出来的，每层都很轻，合起来才叫质感：

1. **聚光** —— 一团柔光跟着指针在卡片里走
2. **边缘高光** —— 同一个圆心，用 `mask` 只留 1.2px 描边，
   于是**亮的那段边框始终朝着鼠标**，指针绕一圈高光跟着转一圈
3. **整卡朝指针那一侧压下去**

位置由一个挂在 `document` 上的委托监听写进 `--mx / --my / --tx / --ty`
（`lib/spotlight.ts`）—— 站内几十处卡片分散在七八个页面里，逐个接
`onPointerMove` 既啰嗦又会漏。rAF 合帧，触摸设备和 `reduced-motion` 直接不启用。

两个坑：

- **写 CSS 变量，别直接写 `style.transform`。** hover 的位移和缩放也在 transform 上，
  两边都改会互相覆盖，交给 CSS 合成才不打架。
- **`perspective()` 必须写在 transform 链最前面、且写在元素自己身上。**
  把 `perspective` 属性挂在卡片上只作用于它的**子元素**，卡片本身照样是平的，
  `rotateX/Y` 出来的是「歪」不是「转」。

带语义色的卡（预警红 / 达标绿）整套跟着自己的颜色走 ——
不然红色卡悬停时亮出一圈蓝边，那不是强调，是打架。

## 9. 无障碍

- 键盘第一下 Tab 是「跳到主内容」，不用穿过整个侧栏
- `:focus-visible` 焦点环只在键盘操作时出现，鼠标点击不出
- 表格：`aria-sort` 标排序方向，方向键移动行焦点，`↵` 打开，`空格` 勾选
- 所有图标按钮都有 `aria-label`；提示气泡用 `[data-tip]`，不替代可读名称
- 顶栏的气泡朝下开 —— 顶栏在屏幕最上沿，朝上会被视口切掉
- 触屏（`hover: none`）下侧栏行高提到 42px，置顶按钮只在已置顶时显示

## 10. 响应式断点

| 宽度 | 变化 |
| --- | --- |
| ≥ 1180px | 看板双栏 |
| < 1180px | 看板转单栏 |
| < 900px | 侧栏转浮层 + 遮罩；顶栏出汉堡；页面内边距收窄 |
| < 768px | **表格整体换成卡片流**，不做横向滚 |
| < 640px | 顶栏隐藏汇率与时钟；页面操作按钮占满一行；批量条贴边 |

表格在窄屏换成卡片而不是横向滚，是因为横向滚的表格在手机上找不到任何一行的全貌 ——
你永远只看得到两列。卡片牺牲密度换可读性，这个交换在手机上是划算的。

## 11. 导航：任何时候都知道自己在哪

侧栏有两级（分组 → 模块）、三种形态（展开 / 图标轨 / 浮层）、还有一个置顶区，
状态一多，「我在哪一级」「这组是开是关」就容易糊。四条规则解决：

**1. 三角在最左边。** 跟子项图标错开一档，层级从缩进就读得出来，不用先看内容再猜。
放右边时它离标题太远，扫视时根本注意不到。

**2. 层级导线。** 子项左边一条竖线挂在分组头下面，选中条正好长在这条线上 ——
「你在这一支」是看出来的，不是数缩进算出来的。

**3. 折叠也不丢方位。** 分组收起后那个链接压根没渲染，`aria-current` 帮不上忙。
所以分组头自己要说话：整行点亮 + 一个圆点，「你在这儿，只是收起来了」。
这需要在组件里自己解一次路径，不能只靠 `NavLink`。

**4. 「常用」是快捷方式，不是位置。** 同一个页面在常用和它本来的分组里各出现一次，
两处都画成实心选中，用户会以为这是两个不同的地方。常用那份用**淡一档**的选中样式
（只染文字、不填背景、不画选中条）+ **虚线**导线 —— 缩进跟别的分组一样
（否则子项看着像一级菜单），但「入口」和「位置」区分得开。

置顶区也能折叠：置顶多了会把下面的分组挤出屏幕。一条都没置顶时整块不渲染，
不留一个空标题。

> ⚠️ 角标和置顶按钮**共用最右边那一格**（交叉淡入淡出：静止看角标，手伸过来换按钮）。
> 早先写成「有角标就不渲染置顶按钮」，结果跟单表（角标 10）永远取消不掉置顶。
> 不并排是因为侧栏最窄 200px，并排会把标题挤没。

## 12. 顶栏：三样东西，各有各的收缩顺序

顶栏从左到右是面包屑、汇率牌、世界时间、三个控件。宽度不够时**谁先让位**
是设计出来的，不是碰巧：

| 视口 | 让掉什么 |
| --- | --- |
| ≤ 1080px | 两个芯片里的「附注」——「几地在上班」和「自定 6.7000」，只留那一个数 |
| ≤ 900px | 出现汉堡按钮，面包屑收窄 |
| ≤ 640px | 汇率牌和时钟芯片整个隐藏 |

右侧三个控件包在 `.topbar-acts` 里，间距从顶栏的 12px 收到 2px —— 散着放会
看着像三件不相干的东西，成组之后是一个工具簇。**推它靠右的是 `.spacer`**，
这一点必须是显式的：`.topbar > * { flex: none }` 曾经把 `.spacer` 的 `flex: 1`
一起干掉（同为 `(0,1,0)`，它写在后面），于是右侧那一串其实没有任何东西在推 ——
看着靠右纯粹因为时钟宽度恰好把中间填满，时钟一隐藏按钮就飘到顶栏正中间去。

### 悬停即展开，点过才钉住

汇率和世界时间这两个面板是**看一眼就走**的东西。为了瞄一眼报价而点两次
（点开、看完再点关），这两次点击是白付的 —— 所以指针停上去就展开。

但面板里又有增删按钮，纯悬停会变成「手一抖面板就没了」。所以：

**悬停是给「看」的，点击是给「改」的。** 一旦在面板里点过任何东西就钉住，
此后只有点外面或按 Esc 才关。主动点开芯片同样算「要改东西」，直接钉住。

三个必要的细节：

- **进 130ms 出 240ms。** 进得太快，横扫过顶栏会一路弹面板；
  出的这 240ms 顺便盖住了触发元素和面板之间那 6px 空隙，指针走过去不会掉。
- **同一时刻只允许一个悬停面板。** 两个芯片挨着放，光靠收起延时不够：
  只要在其中一个里点过东西它就钉住了，这时再悬停旁边那个，
  两块面板会一起摊在屏幕上还互相盖住。Menu 里用一个模块级变量互斥。
- **触摸设备退回点击。** 没有悬停这个状态，`(hover: hover)` 查不到就不启用。

芯片上原来的 `data-tip` 气泡去掉了 —— 悬停已经有更好的回应，
再弹一个气泡就是两个东西抢同一个手势。

### 汇率牌价：盯什么、多久刷一次，自己定

顶栏只放**第一条**盯的牌价，加上「自定」那个核算基准。展开是全表：

- 币种自己加减（31 种，覆盖结算货币和客户所在国），存 localStorage；
- 刷新节奏可配：30 秒 / 1 分钟（默认）/ 5 分钟 / 15 分钟 / 手动；
- 涨跌用**箭头 + 颜色**两个通道。红涨绿跌是中文金融界面的默认读法，
  但颜色不能是唯一通道 —— 它跟站内「珊瑚 = 有问题」的语义正好撞车，
  色觉障碍的人也读不出。方向由箭头说，颜色只是加强。
- 日元、越南盾这类小面值币种按 100 / 10000 报（跟银行牌价一个口径），
  倍数写在币种代码前面 —— 「越南盾 2.65」会被当成一盾两块六。

> ⚠️ **牌价是算出来的，不是抓来的。** 纯前端不联网（产品的承诺就是「不上传任何内容」），
> 所以以账套里那条市场汇率为锚，按一张固定的美元交叉汇率表推出其余币种，
> 再叠一层小幅游走。为什么要让它动：既然让用户配「多久刷一次」，
> 刷完数字纹丝不动这个设置就是假的 —— 与其做个骗人的开关，
> 不如把游走做出来并在面板底部标明是演示行情。
> 游走用两条不同周期的正弦叠加而不是随机数：随机数每次刷新都在 ±0.35% 之间弹，
> 看着像行情崩了。接真行情只需要换掉 `lib/fx.ts` 里的 `quote()` 一个函数。

### 世界时间：把六个数字换成一张对照表

原来六个城市平铺在顶栏上（「厦门 13:21 · 利马 00:21 · 纽约 01:21 · …」），
横着占掉四百多像素，还得靠遮罩加横滚才塞得下。它占的是顶栏最贵的一段地方，
换来的信息是六个数字 —— 而没人会一整天盯着利马几点。

**折叠不是为了省地方而省地方，平铺本来就是错的形式。** 真正要回答的问题不是
「几点」，是「现在能不能打过去」；六个并排的数字答不了这个 —— 你得先知道对方
几点上班，再在脑子里做一次减法。

现在顶栏只留一个芯片：本地时间 + 「几地在上班」（后者是一天里真正会变、也真正
有人关心的那个数，有人在班就点亮成绿色）。点开是一张对照表：

- 横轴是**你的**一天（0–24 点），六行共用同一条轴；
- 每行的亮块是对方 9:00–18:00 换算到你这条轴上的位置，跨你的零点就切成两段，
  被切开的那一头削平 —— 读起来是「一段被轴切断」，不是两段班；
- 本地那行画成虚线描边：它是**参照物**，别人的亮块偏在它哪一侧，
  「早几个钟头 / 晚几个钟头」是看出来的；
- 一条竖线是此刻，铺在整片行上而不是每行画一条（每行一条会被行距切成六截）；
- 周末在时间后面标出星期几，否则「全员灰着」看不出是深夜还是放假。

于是「伦敦要等到我下午四点才上班」变成看一眼的事。

城市自己加减（40 个港口、口岸和客户所在地），**列表第一个就是本地** ——
那条横轴属于谁。换本地就是把它挪到第一位，其余城市的亮块自动按新的轴重算。
删除和「设为本地」两个按钮只在那一行悬停时露出来：面板的常态是「看」，
编辑入口不该一直在那儿抢注意力。

> ⚠️ 城市在列表里的身份是 `时区#序号` 而不是时区。北京、上海、厦门、深圳
> 都是 `Asia/Shanghai`，只用时区当 key 的话它们互相覆盖 ——
> 挑了「厦门」存下来，刷新回来会变成「北京」。

> ⚠️ 时差**必须拿两边的 UTC 偏移相减**，不能拿墙上时间的分钟数相减再折回 ±12 小时。
> 厦门 +8、利马 −5，真实差是 −13 小时；折回 ±12 会算成「+11 小时」—— 方向反了，
> 整条时间带画到轴的另一头去。跨时区的真实差能到 ±26 小时，本来就装不进那个圈。
> 偏移的算法：让 `Intl` 把这一刻在目标时区渲染成年月日时分，再把结果**当成 UTC
> 读回来**和真正的 UTC 相减。夏令时、半小时时区全由 `Intl` 负责，不做手工加减。
> 相减前记得把 `now` 截到整分钟，否则秒和毫秒会让偏移算成 479 而不是 480。

### 外观：明暗 + 主题色 + 密度合成一个入口

这三项都是「装修时设一次」的开关，却各占一个顶栏按钮。合并之后顶栏从四个控件
降到三个，也给时钟腾出了位置。里面用三排**分段器**而不是三个二级菜单：都是
「少数几个互斥选项」，摊开来当前值一眼就看见，不用为了看一眼现在是哪档而多点一次。
